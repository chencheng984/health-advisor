# 综合判断与复核

一位顾问围绕一个决定组织证据。把背景、首选、对照、所在层、行动和追问连起来，用户读完就知道今天做什么，下次看什么。 [六段式顾问剧本](dialogue-playbook.md)

## 把材料收敛到一个首选

1. **先过安全。** 用户描述的症状优先决定转介时效。当前明确急症时，立即给联系当地急救的行动，暂停日常优化。 [转介边界](health-layers.md#转介边界)
2. **定眼下的取舍。** 用已经确认的目标、约束和日期复述这次要决定什么。例如「你这周还得赶早会，要定的是保持原训练，还是先给恢复留时间。」
3. **挑最有分量的证据。** 从每个相关主题取一条发现，核对日期、单位、覆盖、来源和用户反馈。写一个首选句，例如「这周先给睡眠多留半小时。主睡眠结束比上期早，和你说的早会安排对得上。」分数只在能解释首选时补充。 [取数与证据判断](evidence.md)
4. **给适合本人的一步。** 在保命层、恢复层、成长层中点明先处理哪一层。首选用动词开头，写起点、频率或用时、下一次观察窗口、一个改判条件。试行动作明确标试行。

## 证据遇到分叉时这样说

- **两种证据同向。** 用一条数字和一句本人感受接住理由，例如「入睡时刻相近，但起床早了。你也说那几天提前出门，先从能移动的晚间安排腾出时间。」
- **设备和自述对不上。** 并列可回查的记录，留一个核对点。「手表早早结束了记录，你说摘表后又睡了一会儿。先记这几晚的实际起床时间，再看覆盖。」
- **多项同周变动。** 按日期对齐后给重合日数，只用周汇总时说同期。选择证据扎实且和眼下决定最相关的一项行动。给一条可能反转它的条件。
- **来源有变化或记录空白。** 说清变的是哪个指标和来源，保留两边各自的值，其他可比项照常用。一类变化只问一次。专项训练空白和运动时间同时存在时先问实际练过什么，补记后再判断训练量。
- **睡够但节律变化。** 同班型、同口径时长已经达标且起床更晚或波动明显，首选是固定可行的起床时段并留足睡眠机会。近期换班、旅游或记录覆盖变化时，先按可比班型和时区核查。

给条件式判断时写明答案会改哪一步。例如「如果你确实早起，先从晚间挪出半小时。若摘表后还睡了，先补齐实际起床时间。」用户安全或某个关键输入必须先确认时，先问一个会反转结论的问题。其他未知留到结尾，最多 1–2 问。

## 交付按四部分写

1. **结论先行。** 一到两句，先说明最值得做的一件事和理由。
2. **对照。** 一张 2–4 行的表或一句同口径对照。给时期、单位、覆盖、来源和行动含义。无可比基线时用现有观察与缺口。
3. **行动。** 点明优先层、具体动作和适用红线。工作台已生成时附路径与第一步操作。
4. **复核。** 说何时用同一口径看什么，并写什么情况提前处理或改做法。需要时加 1–2 个能改判的问题。 [Markdown 复盘模板](dual-perspective.md)

## 下次回来怎么接

「上次我们选了把工作日起床固定在一个时段。过去 7 天做到了几次，哪天的安排有变化？」先看用户是否执行及被什么打断，再看同口径观测和已约定的改判条件。记录补充是本人反馈。重新选定动作时，告诉对方哪条有效证据改变了原计划。用户没报告新条件时按原窗口复核。

用户同意在本机保留时，可用以下命令。默认记忆文件与所选缓存同目录，新安装通常使用 `~/.health-advisor/memory.json`。

```text
python scripts/health.py memory init
python scripts/health.py memory set goal "固定工作日起床时段"
python scripts/health.py memory set constraint "每周三晚有固定安排"
python scripts/health.py memory review "先固定工作日起床时段" --recheck-on 2026-11-30
```

`memory show` 查看条目与 ID。保存新条目直接运行 `set` 或 `review`，更新已保存条目时追加 `--id ID`。`memory forget ID` 或 `memory forget --all` 会先显示确认文案，重新运行并追加 `--yes` 才清除。`memory export` 将可读 JSON 输出到终端。`brief`、`report` 和 `workbench` 支持 `--memory PATH` 和 `--no-memory`。复核日按本机日期判断，到了复核日先核对上次行动是否完成。
