# 取数与证据判断

先定用户要做的决定，再取能回答它的指标。给每个可用信号留一条可回查的记录。写下窗口、本期或对照、数和单位、有效日或夜、来源以及哪个限制会影响行动。

## 从请求定窗口

1. 在技能目录运行 `python scripts/health.py`，需要 Python 3.10 或以上，计算在本地完成。`--db PATH` 放在子命令前。默认缓存为 `~/.health-advisor/health.sqlite3`，新位置暂无缓存时会继续使用已有的旧版缓存。已有缓存先用 `status` 确认可用指标和版本。用户要求导入时使用 `import PATH`，新导出成功导入后会替换选定缓存。保留历史时用 `import --merge`，分别保存时选独立缓存。没有数据时，引导用户从健康应用导出。
2. 用 `brief` 摘取复盘证据。默认取最新索引日及此前 6 日，并对照紧邻的前 7 日。可用 `--metric` 或 `--group` 缩小范围。「最近有数据的一周」可沿用这个默认末日。「过去 7 天」和「上个日历周」按用户的本地日期设 `--from` 与 `--to`，两端含当天。分数另用已结束的连续 7 个本地日。
3. 短期用上一等长窗口，长期用本期前的个人基线。`--compare-previous` 切换到紧邻的等长窗口，`--baseline-days` 设置基线日历天数，常规 `query` 的默认基线为 90 天。对照窗不相邻时分别取数，只有时间、来源、单位与覆盖可比时才报告差值。
4. 涉及某几天、换表或跨指标同时变化时，用 `query --daily` 查逐日汇总。按归夜日期对齐睡眠和下一天，给出共同日或夜数。作息取 `sleep_details` 的主睡眠起止时刻和时刻跨度。要查某一夜，可将 `--from` 与 `--to` 设为同一归夜日期后查询睡眠。只拿到周汇总时，表述为「同一周都出现」，把解释留到核对后。 [指标、归日与聚合口径](record_types.md)

## 从记录选一句能支撑首选的话

- **设备客观记录**　「手表在 6/7 夜记到睡眠，中位数是 6 小时 10 分。」用数、单位、时间、覆盖和来源。`median` 是有效日或夜的中位数，`period_total` 是有记录的合计。百分比指标的绝对差用百分点。
- **用户自述**　「你说三天都因早会起得更早。」用来核对真实作息、训练、佩戴、饮食或症状。能识别的手填记录归这里。来源不清时标「Apple 健康汇入，采集方式未确认」。
- **待核对的推断**　「早起可能挤掉了一些睡眠。先看这几天实际起床的时刻。」写支持它的记录和一个能改变动作的核对点。两条证据冲突就并列。 [证据分级](health-layers.md#证据分级)

`brief` 的 `coverage.days_after_last_indexed_date` 大于零时在结论附近写缓存截至日。每个指标再查 `last_observation`，指标最后记录日可能更早。明确的零写为零，缺测写「无记录」并标分母。没有当前观测时，能根据用户自述给可逆行动就标注依据。决策必须依赖最新设备观察时，首选补对应区间。

## 看比较状态再写方向

- `comparable`　可用同口径的日值中位数写方向和差值。说「持续」或「越来越」要有逐日证据。作息起止还需核对班型、当地时间和时区偏移，这些条件改变时先描述两边各自的记录。
- `source_changed`　保留两期各自的数、范围和来源，暂缓该项方向与差值。把几项同一来源问题合成一句，再在结尾留一个核对点。
- `insufficient_coverage`　给实际分母和可用值，例如「本期手表只覆盖 2/7 夜，先看哪几晚没有佩戴」。覆盖补齐后再判断两期方向。
- `no_recent_data`　说本期缺哪项、最后有记录是哪天。只有导出没有 `Workout` 时写「专项训练无记录」。有单独的 Apple 运动时间就照口径报告，并问实际训练或漏记。用户确认当周未训练时，才给出自述的零训练。

## 把来源变化说成人话

1. 对照 `comparison.state`、`recent.sources` 与 `comparison_period.sources`，必要时在本地进一步核对缓存来源 ID、采样方式和覆盖。标签相同也可能有设备或佩戴条件变化。用户已确认换表或改 App，就直接复用日期和新来源。
2. 选影响决定的那一项说具体变化。例如「这周的睡眠主要是第三方 App 记的，上周主要是手表。两边各有记录，我先把它们分开看。」其余可比项保留差值和解释。用实际发现的来源类型和称呼。
3. 留一个会改变取数的追问。「你中间换过表，或者改用别的 App 记睡眠了吗？」有同源、同口径且覆盖够的区间时重查。可以在本地用 `--prefer-source ID` 指定优先级，再核对最终实际来源。否则说明现有记录能支持的当前观察和补齐窗口。

训练用 `workout_details` 汇报类型、次数、记录日和分钟。Apple 运动时间单列，做负荷判断前补实际训练与 RPE。旧缓存可读历史汇总，`stage_data_available` 或 `type_data_available` 为 `false` 时说明明细缺口，需要时用用户提供的原 ZIP 重新导入。`inventory_only` 和附件计数用于盘点。需要 ECG 或 GPX 专项信息时，只引用当前版本实际返回且与决定有关的摘要，遵守 [转介与附件边界](health-layers.md#转介边界)。
